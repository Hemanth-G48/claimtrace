Problem Statement 1: Trust Nothing, Provenance for Your Own Dependencies The problem. Modern software supply-chain attacks (typosquatting, dependency confusion, malicious install scripts) succeed because developers can't quickly tell whether a package they're about to install behaves differently from what it claims. Existing scanners mostly match known-bad signatures, so they miss new attacks. The challenge. Build a tool that takes a small package (npm or PyPI style) and produces a behavioral fingerprint of what it does at install and import time: network calls attempted, files touched, environment variables read, subprocesses spawned. It then compares that fingerprint to what the package's own README and metadata claim it does, and flags mismatches. For example, a "left-pad" style string utility that tries to read ~/.ssh or contact an external host should be flagged.
